# شروع سریع — از صفر تا اولین فروش

این راهنما گام‌به‌گام شما را تا نقطه‌ای می‌برد که اولین مشتری بتواند سرور بخرد.

---

## گام ۱ — پیش‌نیازها روی سرور

```bash
# Node.js 22 LTS
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs

# PostgreSQL
sudo apt install -y postgresql postgresql-contrib

# ساخت دیتابیس و کاربر
sudo -u postgres psql <<'SQL'
CREATE USER pasargad WITH PASSWORD 'یک-رمز-قوی-اینجا';
CREATE DATABASE pasargad_cloud OWNER pasargad ENCODING 'UTF8';
SQL
```

---

## گام ۲ — دریافت توکن هتزنر

1. وارد [console.hetzner.cloud](https://console.hetzner.cloud) شوید.
2. یک **Project** بسازید (یا موجود را انتخاب کنید).
3. از منوی راست: **Security → API Tokens → Generate API Token**
4. دسترسی را روی **Read & Write** بگذارید.
5. توکن را کپی کنید — فقط یک بار نمایش داده می‌شود.

> کل فروش شما داخل همین پروژه هتزنر انجام می‌شود. برای تفکیک حسابداری می‌توانید پروژه‌ای مجزا از سرورهای شخصی خود بسازید.

> **سقف پروژه.** هر پروژه هتزنر به‌طور پیش‌فرض فقط ۱۰ سرور می‌پذیرد. اگر بیشتر می‌فروشید،
> چند پروژه یا چند حساب بسازید و توکن هرکدام را در گام ۶ به پنل اضافه کنید؛ پنل هر وقت
> ظرفیت یکی پر شد، خودکار سراغ بعدی می‌رود. توکن‌ها در فایل `.env` نمی‌روند.

## گام ۳ — تنظیم فایل محیط

```bash
cp .env.example .env
```

سپس مقادیر زیر را پر کنید:

```bash
APP_URL=https://panel.yourdomain.ir
DATABASE_URL="postgresql://pasargad:رمز-شما@localhost:5432/pasargad_cloud?schema=public"

# این دو را با دستورهای زیر بسازید و جایگذاری کنید
SESSION_SECRET=
ENCRYPTION_KEY=

ZIBAL_MERCHANT=کد-مرچنت-زیبال
```

> توکن هتزنر اینجا نوشته نمی‌شود؛ آن را در گام ۶ از خود پنل اضافه می‌کنید تا رمزنگاری‌شده
> در دیتابیس ذخیره شود و بتوانید هر تعداد حساب داشته باشید.

ساخت کلیدها:

```bash
node -e "console.log('SESSION_SECRET=' + require('crypto').randomBytes(48).toString('base64url'))"
node -e "console.log('ENCRYPTION_KEY=' + require('crypto').randomBytes(32).toString('hex'))"
```

> **هرگز `ENCRYPTION_KEY` را بعد از شروع فروش تغییر ندهید.** رمز روت تمام سرورهای مشتریان با همین کلید رمزنگاری می‌شود.

## گام ۴ — راه‌اندازی

```bash
npm ci
npm run build
npm run db:push
npm run db:seed
```


## گام ۵.۵ — سرویس آزمایش دسترسی از ایران

این گام اختیاری نیست اگر می‌خواهید مشتری هیچ‌وقت سروری با آی‌پی فیلترشده تحویل نگیرد.

هتزنر آی‌پی تصادفی می‌دهد و بخشی از رنج‌هایش در ایران مسدود است. پنل شما روی سرور خارج
اجرا می‌شود و خودش نمی‌فهمد یک آدرس از داخل ایران باز می‌شود یا نه. پس یک سرویس کوچک
روی یکی از سرورهای ایرانی خودتان بگذارید:

```bash
# روی سرور ایرانی
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"   # کلید بسازید
IRAN_PROBE_SECRET=کلید-ساخته‌شده PORT=8787 node iran-probe-agent.mjs
```

سپس در `.env` پنل:

```bash
IRAN_PROBE_URL=https://probe.yourdomain.ir
IRAN_PROBE_SECRET=همان-کلید
```

از این پس آدرس هر سرور تازه پیش از تحویل آزمایش می‌شود و اگر از ایران باز نشود، پنل
خودش و رایگان عوضش می‌کند. وضعیت در `/admin/ip-health` دیده می‌شود.

## گام ۶ — افزودن حساب هتزنر و دریافت کاتالوگ

ابتدا `/admin/hetzner` → دکمه **افزودن حساب**:

| فیلد | مقدار |
|---|---|
| نام حساب | یک برچسب دلخواه، مثلاً «هتزنر اصلی» |
| توکن API | توکنی که در گام ۲ گرفتید |
| سقف تعداد سرور | سقف پروژه‌تان در هتزنر (پیش‌فرض ۱۰) |
| اولویت | ۰ برای حساب اصلی، ۱ و ۲ و … برای بعدی‌ها |

پیش از ثبت، دکمه **آزمایش** اتصال را بررسی می‌کند. اگر چند حساب دارید، همه را همین‌جا
اضافه کنید؛ ظرفیتشان روی هم جمع می‌شود و به ترتیب اولویت مصرف می‌شود.

سپس `/admin/catalog` → دکمه **همگام‌سازی با هتزنر**

پس از چند ثانیه تمام پلن‌ها، لوکیشن‌ها و سیستم‌عامل‌ها دریافت می‌شوند.

سپس تصمیم بگیرید چه چیزی بفروشید:

- پلن‌هایی که نمی‌خواهید بفروشید را خاموش کنید (مثلاً پلن‌های خیلی گران).
- لوکیشن‌هایی که برای مشتریان ایرانی مناسب نیست را خاموش کنید.
- سیستم‌عامل‌های غیرضروری را خاموش کنید تا صفحه خرید شلوغ نشود.

## گام ۷ — تعیین قیمت

`/admin/pricing`

| تنظیم | توضیح | پیشنهاد شروع |
|---|---|---|
| نرخ هر یورو | باید با نرخ خرید ارز شما بخواند | نرخ روز + ۳٪ حاشیه نوسان |
| درصد سود | سود شما روی قیمت هتزنر | ۲۵ تا ۴۰ درصد |
| مبلغ ثابت | پوشش کارمزد درگاه و پشتیبانی | ۲۰٬۰۰۰ تا ۵۰٬۰۰۰ تومان |
| گرد کردن ماهانه | زیبایی قیمت | ۱۰٬۰۰۰ تومان |

در جدول **پیش‌نمایش قیمت نهایی**، ستون «سود ماهانه شما» را ببینید و اعداد را تا رسیدن به حاشیه سود مطلوب تنظیم کنید.

**قوانین اختصاصی** برای موارد زیر مفیدند:

- پلن‌های ارزان که حاشیه سود درصدی‌شان کم است → درصد بالاتر بدهید.
- لوکیشن‌های پرتقاضا → درصد بالاتر.
- مشتریان عمده → قانون از نوع «کاربر مشخص» با درصد کمتر، یا تخفیف اختصاصی در صفحه کاربر.

> **مهم:** نرخ یورو را هفتگی به‌روز کنید. قیمت سرورهای فعال تغییر نمی‌کند و فقط روی خریدهای جدید اثر دارد.

## گام ۸ — تنظیم درگاه پرداخت

`/admin/settings`

آدرس بازگشت را از همان صفحه کپی و در پنل زیبال ثبت کنید:

```
https://panel.yourdomain.ir/api/wallet/callback
```

اگر کارت به کارت هم می‌پذیرید، «واریز کارت به کارت» را روشن و شماره کارت را در کادر مربوطه بنویسید. رسیدها در `/admin/transactions` با فیلتر «در انتظار» برای تایید شما می‌آیند.

---

## گام ۹ — تنظیم چرخه سرویس

`/admin/settings` → بخش «چرخه سرویس و تعلیق»

| تنظیم | معنی | پیشنهاد |
|---|---|---|
| حداقل اعتبار سرور ساعتی | مانع ساخت سرور با اعتبار ناکافی | ۲۴ ساعت |
| مهلت پس از اتمام موجودی | فرصت شارژ قبل از قطع | ۶ تا ۱۲ ساعت |
| نگهداری داده پس از تعلیق | فرصت بازگشت مشتری | ۷ روز |

> هرچه مهلت‌ها بیشتر باشد، ریسک بدهی شما به هتزنر بالاتر می‌رود. تعادل را با توجه به توان مالی خود تعیین کنید.

## گام ۱۰ — آزمایش پایانی

```bash
npm run health
```

باید همه موارد سبز باشند. سپس:

1. با یک ایمیل دیگر یک حساب مشتری آزمایشی بسازید.
2. با مبلغ کم (مثلاً ۱۰ هزار تومان) کیف پول را از درگاه واقعی شارژ کنید.
3. از `/admin/users` به آن حساب موجودی دستی اضافه کنید.
4. ارزان‌ترین سرور ساعتی را بسازید و ورود SSH را تست کنید.
5. سرور را حذف کنید و برگشت وجه دوره استفاده‌نشده را بررسی کنید.

اگر این چرخه بدون خطا کامل شد، آماده فروش هستید.

## نکات مالی مهم

**مجموع موجودی کاربران بدهی شماست.** در داشبورد مدیریت این عدد نمایش داده می‌شود. همیشه باید معادل نقدی آن را در دسترس داشته باشید.

**هتزنر ماهانه از شما صورتحساب می‌گیرد، ولی شما ساعتی از مشتری می‌گیرید.** پس در ابتدای کار جریان نقدی مثبت است؛ فریب آن را نخورید و ذخیره پرداخت به هتزنر را کنار بگذارید.

**سقف ماهانه.** سرور ساعتی هرگز در یک ماه بیش از قیمت ماهانه‌اش هزینه نمی‌گیرد — دقیقاً همان قاعده هتزنر — پس ضرر نمی‌کنید.

**سرور خاموش هم هزینه دارد.** هتزنر برای سرور خاموش هم هزینه می‌گیرد چون منابع رزرو می‌ماند. پنل هم همین کار را می‌کند. این نکته را در قوانین سایت خود شفاف بنویسید تا اعتراض مشتری پیش نیاید.
