# وبلاگ و سئو

راهنمای کامل وبلاگ پاسارگاد میزبان: چه چیزی ساخته شده، چطور از آن استفاده کنید و برای رتبه گرفتن در گوگل دقیقاً چه کارهایی باید انجام دهید.

---

## ۱) راه‌اندازی، یک بار برای همیشه

### گام اول: مهاجرت دیتابیس

مدل‌های وبلاگ به schema اضافه شده‌اند، پس یک بار باید دیتابیس را به‌روز کنید:

```bash
npm run db:push
```

این پروژه جدول‌ها را با `prisma db push` می‌سازد (پوشه migrations ندارد)، پس همان دستور بالا در محیط عملیاتی هم کافی است. پیش از اجرا در سرور، از دیتابیس بکاپ بگیرید.

### گام دوم: محتوای آغازین (اختیاری ولی توصیه‌شده)

پنج مقاله کامل و چهار دسته آماده، با ساختار سئویی درست:

```bash
npm run blog:seed            # مقاله‌های موجود دست‌نخورده می‌مانند
npm run blog:seed -- --force # بازنویسی همان مقاله‌ها
```

متن مقاله‌ها در `scripts/blog-seed/` است؛ قبل یا بعد از اجرا می‌توانید ویرایششان کنید. **توصیه:** هر مقاله را با جمله‌ها و مثال‌های خودتان بازنویسی کنید؛ محتوای یکتا همیشه بهتر رتبه می‌گیرد.

### گام سوم: تنظیمات سئو در پنل

به **مدیریت ← وبلاگ ← تنظیمات سئو** بروید و این‌ها را پر کنید:

| تنظیم | چرا مهم است |
| --- | --- |
| آدرس کامل سایت | مبنای canonical، نقشه سایت، RSS و داده ساخت‌یافته. اگر غلط باشد، هیچ چیز دیگری درست کار نمی‌کند |
| عنوان و توضیح وبلاگ | همان متنی که در نتایج گوگل برای `/blog` دیده می‌شود |
| تصویر پیش‌فرض اشتراک‌گذاری | کارت لینک در تلگرام و شبکه‌های اجتماعی (۱۲۰۰×۶۳۰) |
| کد تأیید گوگل سرچ کنسول | برای ثبت سایت و دیدن جایگاه کلمات |

### گام چهارم: ثبت در گوگل سرچ کنسول

۱. در [search.google.com/search-console](https://search.google.com/search-console) سایت را اضافه کنید (روش HTML tag).
۲. کد تأیید را در پنل، بخش تنظیمات سئو بگذارید و ذخیره کنید.
۳. در سرچ کنسول روی Verify بزنید.
۴. در بخش Sitemaps، آدرس `دامنه-شما/sitemap.xml` را ثبت کنید.
۵. در بینگ وبمستر هم همین کار را انجام دهید (ترافیک کمتر، ولی رایگان است و سریع ایندکس می‌کند).

## ۱.۴) ساخت حساب مدیر

روی نصبی که فقط وبلاگ است، ثبت‌نام عمومی را می‌بندید؛ حساب مدیر را با یک دستور بسازید:

```bash
npm run admin:create -- --email admin@example.com
# داکر:
docker compose run --rm app npm run admin:create -- --email admin@example.com
```

رمز قوی خودش ساخته و **یک بار** چاپ می‌شود؛ همان لحظه ذخیره‌اش کنید. گزینه‌های دیگر:

| سوییچ | کار |
| --- | --- |
| `--password 'MyPass123'` | رمز دلخواه (حداقل ۸ نویسه، شامل حرف و رقم) |
| `--reset` | روی حساب موجود، فقط رمز تازه بساز |
| `--name` و `--lastname` | نام نمایشی حساب |

اگر ایمیل از قبل وجود داشته باشد، همان حساب به «مدیر» ارتقا می‌یابد (و با `--reset` رمزش هم عوض می‌شود). بعد از ورود، از `/dashboard/profile` رمز را عوض کنید و ورود دو مرحله‌ای را روشن کنید.

## ۱.۵) برند، رنگ و آدرس پنل ابری

وبلاگ می‌تواند روی سروری جدا از پنل ابری باشد. در این حالت سه آدرس در کار است و هر سه در **مدیریت ← سئو و آمار ← تنظیمات سئو** تنظیم می‌شود:

| تنظیم | مثال | کاربرد |
| --- | --- | --- |
| آدرس همین سایت (وبلاگ) | `https://blog.example.com` | مبنای canonical، نقشه سایت و RSS |
| آدرس سایت اصلی | `https://example.com` | لوگوی سربرگ و لینک «صفحه اصلی» |
| **آدرس پنل ابری** | `https://cloud.example.com` | **همه دکمه‌های فروش و لینک‌های داخلی مقاله‌ها** |

وقتی آدرس پنل ابری تنظیم شود، این‌ها همه به آن می‌روند: دکمه سربرگ، جعبه فروش کنار مقاله، دعوت پایان مقاله، لینک‌های پابرگ، و لینک‌های داخلی که نویسنده هوش مصنوعی در متن می‌گذارد. متن دکمه هم قابل تغییر است (پیش‌فرض: «ساخت سرور ساعتی»).

لینک به دامنه‌های خودتان (سایت اصلی و پنل ابری) **لینک داخلی** حساب می‌شود: نه `nofollow` می‌خورد و نه در دروازه کیفیت «لینک بیرونی» شمرده می‌شود.

### رنگ برند

در همان صفحه، فیلد **رنگ اصلی برند** هست. کد رنگ سایت اصلی را بگذارید (یا از انتخابگر رنگ استفاده کنید)؛ طیف کامل ۵۰ تا ۹۵۰ از همان ساخته می‌شود و دکمه‌ها، لینک‌ها، تیترها و جعبه‌های وبلاگ همان رنگ می‌گیرند. نیازی به بیلد دوباره یا دست زدن به CSS نیست — ذخیره کنید و صفحه را تازه کنید.

## ۲) چه چیزی ساخته شده است

### صفحه‌های عمومی

| آدرس | توضیح |
| --- | --- |
| `/blog` | فهرست مقاله‌ها، مقاله ویژه، جستجو، صفحه‌بندی با لینک واقعی |
| `/blog/<نشانی-مقاله>` | صفحه مقاله با فهرست مطالب، پرسش‌های پرتکرار، جعبه نویسنده و مقاله‌های مرتبط |
| `/blog/category/<دسته>` | صفحه دسته با عنوان و توضیح متای مستقل |
| `/blog/tag/<برچسب>` | صفحه برچسب (برچسب با کمتر از ۳ مقاله خودکار noindex می‌شود) |
| `/blog/rss.xml` | خوراک RSS با متن کامل مقاله‌ها |
| `/sitemap.xml` | نقشه سایت خودکار: صفحه اصلی، وبلاگ، دسته‌ها، مقاله‌ها |
| `/robots.txt` | اجازه خزش وبلاگ، بستن پنل و APIها |

### پنل مدیریت

**مدیریت ← وبلاگ** سه بخش دارد:

- **مقاله‌ها** — فهرست با وضعیت، امتیاز سئو، بازدید و دسته؛ ساخت، ویرایش، ویژه کردن و حذف.
- **دسته‌ها** — ساخت دسته با عنوان و توضیح متای جدا.
- **تنظیمات سئو** — آدرس سایت، عنوان وبلاگ، کدهای تأیید و نشانی‌های فنی.

### ویرایشگر مقاله

- نوشتن با مارک‌داون و پیش‌نمایش زنده
- **امتیاز سئو زنده** با ۱۷ بررسی (طول عنوان، چگالی کلیدواژه، لینک داخلی، تیتربندی، خوانایی و…)
- **پیش‌نمایش نتیجه گوگل**: دقیقاً همان چیزی که کاربر در نتایج می‌بیند
- پرسش‌های پرتکرار (داده ساخت‌یافته FAQ)
- زمان‌بندی انتشار، مقاله ویژه، noindex، canonical سفارشی
- نام و تخصص نویسنده (سیگنال اعتبار محتوا)

### آنچه خودکار انجام می‌شود

- **عنوان و توضیح متا، canonical، Open Graph و کارت توییتر** برای هر صفحه
- **داده ساخت‌یافته** (JSON-LD): `Organization`، `WebSite`، `BreadcrumbList`، `BlogPosting`، `FAQPage`، `ItemList`
- **ریدایرکت ۳۰۱ هنگام تغییر نشانی مقاله** — نشانی قدیمی ذخیره و به نشانی تازه هدایت می‌شود، پس رتبه از دست نمی‌رود
- شناسه (id) روی تیترها + فهرست مطالب، برای لینک پرش در نتایج گوگل
- زمان مطالعه، شمار کلمه، شمار بازدید
- خلاصه خودکار اگر خودتان ننویسید
- `loading="lazy"` روی تصویرهای متن و بارگذاری فوری تصویر شاخص (برای LCP سریع)

### نشانه‌گذاری‌های مارک‌داون

| نشانه | نتیجه |
| --- | --- |
| `## تیتر` | تیتر H2 (در فهرست مطالب می‌آید) |
| `### تیتر` | تیتر H3 |
| `**پررنگ**` / `*مورب*` | تأکید |
| `- مورد` / `۱. مورد` | فهرست |
| `[متن](/register)` | لینک (لینک بیرونی خودکار `rel="noopener nofollow"` می‌گیرد) |
| `![توضیح تصویر](آدرس)` | تصویر با متن جانشین |
| `` ```bash `` | بلوک کد |
| `\| ستون \| ستون \|` | جدول |
| `:::tip` … `:::` | جعبه نکته (`tip`، `warning`، `note`) |
| `> متن` | نقل قول |

> تیتر `#` خودکار به H2 تبدیل می‌شود، چون در هر صفحه فقط یک H1 (عنوان مقاله) مجاز است.

## ۳) نقشه راه رتبه گرفتن

رتبه گرفتن در گوگل میان‌بر ندارد، ولی ترتیب درست کارها سرعت را چند برابر می‌کند. این برنامه سه‌ماهه را پیشنهاد می‌کنیم.

### ماه اول: پایه و محتوای ستون

۱. **۱۰ تا ۱۵ مقاله منتشر کنید.** هفته‌ای دو تا سه مقاله ۹۰۰ تا ۱۵۰۰ کلمه‌ای.
۲. **روی عبارت‌های کم‌رقابت شروع کنید.** «سرور مجازی» را فعلاً فراموش کنید؛ عبارت‌های دقیق‌تر سریع‌تر رتبه می‌گیرند:
   - «رفع خطای Connection timed out سرور»
   - «آموزش نصب داکر روی اوبونتو ۲۴.۰۴»
   - «تفاوت پردازنده مشترک و اختصاصی سرور»
   - «چرا سرور آلمان از ایران باز نمی‌شود»
۳. **هر مقاله را به دو سه مقاله دیگر و به صفحه خرید لینک بدهید.**
۴. **بعد از هر انتشار، در سرچ کنسول آدرس را URL Inspection → Request Indexing کنید.**

### ماه دوم: خوشه موضوعی

برای هر دسته، یک **مقاله مرجع بلند** (۲۰۰۰+ کلمه) بنویسید و همه مقاله‌های ریز آن موضوع را به آن لینک کنید و برعکس. گوگل این ساختار را «خوشه موضوعی» می‌بیند و سایت را در آن حوزه معتبر می‌شناسد.

نمونه خوشه برای میزبانی:

| مقاله مرجع | مقاله‌های پیرامون |
| --- | --- |
| راهنمای کامل خرید سرور مجازی | انتخاب لوکیشن، پردازنده مشترک یا اختصاصی، محاسبه ترافیک، مقایسه قیمت |
| راهنمای کامل امنیت سرور لینوکس | فایروال، SSH با کلید، Fail2ban، SSL رایگان، بکاپ |
| آموزش مدیریت سرور با لینوکس | اتصال SSH، مدیریت سرویس‌ها، لاگ‌ها، فضای دیسک |

### ماه سوم: بهینه‌سازی و اعتبار بیرونی

- در سرچ کنسول ببینید کدام مقاله‌ها در جایگاه ۸ تا ۲۰ هستند؛ **همان‌ها را کامل‌تر کنید**. ارتقای مقاله‌ای که در جایگاه ۱۲ است، چند برابر نوشتن مقاله تازه بازده دارد.
- عبارت‌هایی که کاربر جستجو کرده ولی مقاله‌ای برایشان ندارید (Queries) را به فهرست نوشتن اضافه کنید.
- در انجمن‌ها و شبکه‌های اجتماعی تخصصی، جایی که پاسخ واقعی به پرسش کسی است، به مقاله‌تان لینک بدهید. چند لینک طبیعی مرتبط، از صد لینک بی‌ربط بهتر است.
- مقاله‌های قدیمی را هر سه ماه به‌روز کنید؛ تاریخ به‌روزرسانی در صفحه و در داده ساخت‌یافته نمایش داده می‌شود.

### چک‌لیست پیش از انتشار هر مقاله

- [ ] کلیدواژه هدف مشخص است و در عنوان، نشانی، پاراگراف اول و یکی از تیترها آمده
- [ ] عنوان سئو زیر ۶۰ نویسه، توضیح متا بین ۱۲۰ تا ۱۶۰ نویسه
- [ ] دست‌کم ۷۰۰ کلمه (برای عبارت‌های رقابتی ۱۲۰۰+)
- [ ] سه تیتر H2 یا بیشتر
- [ ] سه لینک داخلی و یک لینک به منبع معتبر بیرونی
- [ ] تصویر شاخص با متن جانشین
- [ ] دو پرسش پرتکرار یا بیشتر
- [ ] امتیاز سئو بالای ۸۰
- [ ] پس از انتشار: درخواست ایندکس در سرچ کنسول

### آنچه رتبه را خراب می‌کند

- **کپی کردن محتوا** از سایت دیگر یا تولید انبوه متن بی‌ارزش. گوگل سال‌هاست این را تشخیص می‌دهد.
- **تکرار بی‌رویه کلیدواژه.** چگالی بالای ۳٪ علامت اسپم است.
- **حذف مقاله‌ای که رتبه دارد.** به جای حذف، به‌روزش کنید یا با ریدایرکت به مقاله‌ای مرتبط‌تر هدایتش کنید.
- **تغییر نشانی مقاله بدون دلیل.** ریدایرکت خودکار انجام می‌شود، ولی رتبه معمولاً چند هفته نوسان می‌کند.
- **صفحه‌های کم‌محتوا.** به جای ۱۰۰ مقاله ۳۰۰ کلمه‌ای، ۲۰ مقاله کامل بنویسید.

## ۴) سرعت صفحه

گوگل سرعت را در رتبه حساب می‌کند. آنچه از قبل انجام شده: فونت محلی، تصویر lazy، بدون کتابخانه سنگین مارک‌داون، کوئری‌های ایندکس‌دار.

صفحه‌های وبلاگ در زمان درخواست رندر می‌شوند (چون پروژه بدون دیتابیس بیلد می‌شود). پاسخ‌ها حدود ۵۰ میلی‌ثانیه است؛ اگر ترافیک وبلاگ زیاد شد، ساده‌ترین قدم بعدی گذاشتن یک کش CDN یا پروکسی معکوس (مثل Nginx با `proxy_cache`) جلوی مسیرهای `/blog`، `/sitemap.xml` و `/blog/rss.xml` است.

تصویرها را هم پیش از آپلود بهینه کنید: عرض حداکثر ۱۶۰۰ پیکسل، فرمت WebP، حجم زیر ۲۰۰ کیلوبایت.

## ۵) تولید خودکار محتوا

خط تولیدی که هر روز موضوع‌های پرجستجوی حوزه میزبانی و سرور را پیدا می‌کند و برایشان مقاله می‌نویسد.

### دقیقاً چه می‌کند و چه نمی‌کند

**می‌کند:** از سرویس پیشنهاد جستجوی گوگل (همان پیشنهادهایی که زیر کادر جستجو ظاهر می‌شود) موضوع‌هایی را که مردم واقعاً جستجو می‌کنند استخراج می‌کند، پرسش‌های کاربران را جمع می‌کند، و برای همان موضوع یک مقاله **تازه و اصیل** به فارسی می‌نویسد؛ با لینک داخلی به صفحه‌های فروش و مقاله‌های مرتبط، پرسش‌های پرتکرار و متادیتای کامل.

**نمی‌کند:** مقاله سایت‌های دیگر را برنمی‌دارد و بازنویسی نمی‌کند. این را عمداً این‌طور ساخته‌ام و دلیلش دو چیز است:

- **حق نشر.** برداشتن متن دیگران — حتی با تغییر جمله‌ها — نقض حق نشر است و برای یک کسب‌وکار ثبت‌شده ریسک حقوقی دارد.
- **جریمه گوگل.** سیاست هرزنامه گوگل دو بند دقیقاً برای همین کار دارد: «محتوای کپی‌شده» و «سوءاستفاده از محتوای تولید انبوه». نتیجه‌اش رتبه گرفتن نیست؛ از دست دادن اعتبار کل دامنه است. پس عملاً نتیجه‌ای برعکس هدف شما می‌داد.

راهی که جواب می‌دهد همین است: بفهمیم مردم چه می‌پرسند و پاسخ بهتری از نتایج موجود بنویسیم.

### راه‌اندازی

۱. کلید API مدل زبانی را در `.env` سرور بگذارید:

```bash
ANTHROPIC_API_KEY="sk-ant-..."
CONTENT_MODEL=claude-opus-5-5
```

۲. (اختیاری، ولی کیفیت تحقیق را بالا می‌برد) کلید یک سرویس دارای مجوز خواندن نتایج گوگل:

```bash
CONTENT_SERP_PROVIDER=serper      # یا serpapi
CONTENT_SERP_KEY="..."
```

بدون این کلید هم سیستم کار می‌کند و تحقیق را با پیشنهادهای جستجوی گوگل انجام می‌دهد. با آن، نتایج بالای گوگل و پرسش‌های «دیگران این را هم می‌پرسند» هم به خلاصه تحقیق اضافه می‌شود.

۳. جدول‌ها را بسازید و اپلیکیشن و ورکر را دوباره راه‌اندازی کنید:

```bash
npm run db:push
```

۴. پیش‌فرض‌ها از قبل روشن‌اند: **تولید روزانه فعال، ۳ مقاله در روز، انتشار خودکار روشن، حداقل امتیاز سئو ۸۰**. در **مدیریت ← وبلاگ ← تولید خودکار** می‌توانید هر کدام را تغییر دهید؛ پیش از آن یک بار «تولید همین حالا» را با تعداد ۱ بزنید و خروجی را بخوانید.

### مسیر هر مقاله

۱. **کشف موضوع** — پیشنهادهای جستجوی گوگل برای عبارت‌های پایه حوزه (سرور مجازی، هاست وردپرس، امنیت سرور، لینوکس و…) گرفته و امتیازدهی می‌شود. موضوع‌های تکراری، موضوع‌هایی که مقاله دارند، و موضوع‌های بی‌ربط حذف می‌شوند.
۲. **تحقیق** — پرسش‌های کاربران، عبارت‌های مرتبط و (در صورت تنظیم کلید) عنوان و خلاصه نتایج بالای گوگل جمع می‌شود.
۳. **نوشتن** — مدل با خلاصه تحقیق، فهرست لینک‌های داخلی مجاز و دسته‌های وبلاگ، مقاله را از صفر می‌نویسد.
۴. **دروازه کیفیت** — مقاله باید همه این‌ها را بگذراند، وگرنه رد می‌شود و منتشر نمی‌شود.
۵. **انتشار** — در دسته مناسب ذخیره می‌شود؛ پیش‌نویس (پیش‌فرض) یا منتشرشده.

### دروازه کیفیت چه چیزهایی را رد می‌کند

| بررسی | شرط |
| --- | --- |
| طول متن | از حد تنظیم‌شده کمتر نباشد (پیش‌فرض ۷۰۰ کلمه متن خالی) |
| ساختار | دست‌کم ۳ سرفصل `##` و بدون تیتر سطح یک |
| لینک داخلی | دست‌کم ۲ لینک |
| امتیاز سئو | از حد تنظیم‌شده کمتر نباشد (پیش‌فرض ۷۵) |
| اصالت در برابر منابع | هیچ دنباله ۸ کلمه‌ای مشترک با خلاصه نتایج گوگل |
| اصالت در برابر خودمان | شباهت زیر ۲۰٪ با هر مقاله موجود وبلاگ |

مقاله‌های ردشده با دلیل دقیق در صف می‌مانند تا ببینید چه چیزی ایراد داشته است.

### هزینه

هزینه فقط هزینه مدل است و در پنل، مصرف توکن ۳۰ روز گذشته نمایش داده می‌شود. برای مقاله‌های ۱۰۰۰ تا ۱۴۰۰ کلمه‌ای، هر مقاله معمولاً بین **۰.۱ تا ۰.۳ دلار** تمام می‌شود؛ یعنی سه مقاله در روز حدود **۱۰ تا ۲۵ دلار در ماه**. این یک تخمین است، نه قیمت تضمینی؛ عدد واقعی را بعد از چند روز از همان شمارنده پنل ببینید.

### کیفیت نوشتار

پرامپت نویسنده طوری نوشته شده که متن، شبیه نوشته یک مهندس باشد نه یک تولیدکننده متن: جمله کوتاه و بلند قاطی، جزئیات مشخص (نام نسخه، مسیر فایل، دستور واقعی)، بدون مقدمه‌چینی و بدون کلیشه. فهرستی از عبارت‌های کلیشه‌ای («در دنیای امروز»، «لازم به ذکر است»، «امیدواریم مفید بوده باشد» و…) هم در پرامپت ممنوع شده و هم در دروازه کیفیت بررسی می‌شود؛ مقاله‌ای که این عبارت‌ها را داشته باشد رد می‌شود. سرفصل‌های بی‌محتوا («مقدمه»، «نتیجه‌گیری») هم رد می‌شوند.

یک نکته صریح: هیچ ترفندی برای فریب ابزارهای تشخیص هوش مصنوعی پیاده نشده و پیاده هم نمی‌شود. آن ترفندها (درهم‌ریختن واژه‌ها، نویسه‌های نامرئی و…) کیفیت متن را پایین می‌آورند و در رتبه گوگل اثری ندارند. گوگل محتوای تولیدشده با هوش مصنوعی را ممنوع نکرده؛ محتوای بی‌ارزش و انبوه را جریمه می‌کند. تنها راه واقعی «مشخص نشدن»، متنی است که واقعاً به پرسش کاربر پاسخ می‌دهد — و همان چیزی است که رتبه هم می‌آورد.

### توصیه درباره سرعت انتشار

انتشار خودکار روزی ۳ مقاله روشن است، چون همین خواسته شده. دو چیز را بدانید:

- **هر چند روز، چند مقاله را بخوانید.** مدل ممکن است جزئیات فنی را اشتباه بنویسد و یک دستور لینوکس غلط، اعتماد خواننده فنی را از بین می‌برد. مقاله منتشرشده را می‌توانید همان لحظه در پنل ویرایش کنید.
- **اگر وبلاگ تازه است، یک ماه اول را با روزی ۱ یا ۲ مقاله جلو بروید.** انتشار ناگهانی حجم زیاد روی دامنه‌ای بدون سابقه انتشار، همان الگویی است که گوگل «تولید انبوه» می‌بیند. برای تغییر، فقط عدد «تعداد در روز» را در پنل کم کنید.

### عیب‌یابی

**«کلید ANTHROPIC_API_KEY تنظیم نشده است»** — کلید را در `.env` بگذارید و هم اپلیکیشن و هم ورکر (`npm run worker`) را دوباره راه‌اندازی کنید.

**«موضوع تازه‌ای پیدا نشد»** — همه عبارت‌های کشف‌شده قبلاً استفاده شده‌اند. عبارت‌های پایه در `src/lib/content/keywords.ts` (ثابت `SEED_KEYWORDS`) هستند؛ چند عبارت تازه مربوط به سرویس‌های خودتان اضافه کنید.

**مقاله‌ها مرتب رد می‌شوند** — دلیل هر رد در صف نوشته شده است. اگر دلیلش امتیاز سئو است، حد را موقتاً به ۷۰ کم کنید؛ اگر طول است، حد کلمه را واقعی‌تر کنید.

**تولید روزانه اجرا نمی‌شود** — ورکر باید دائم در حال اجرا باشد (`npm run worker` یا سرویس `worker` در docker-compose). ساعت اجرا به وقت تهران است و کرون هر ساعت دقیقه ۵۰ بیدار می‌شود.

**موضوع‌های مربوط به ابزارهای دور زدن فیلترینگ** (v2ray، فیلترشکن و…) عمداً از فهرست کشف حذف شده‌اند. اگر می‌خواهید درباره‌شان بنویسید، آگاهانه و دستی بنویسید؛ در `keywords.ts` فهرست `BLOCKED` را ببینید.

## ۶) بخش «سئو و آمار» در پنل

مسیر: **مدیریت ← سئو و آمار** (`/admin/seo`). سه بخش دارد.

### داشبورد سئو

- **آمار واقعی گوگل** (در صورت اتصال سرچ کنسول): کلیک، نمایش، میانگین جایگاه و نرخ کلیک در ۲۸ روز گذشته، همراه مقایسه با بازه قبل؛ عبارت‌هایی که با آن‌ها دیده می‌شوید و صفحه‌های پربازدید.
- **امتیاز سلامت سئو** از ۱۰۰، بر اساس بررسی‌های درون‌سایتی.
- **چک‌لیست فنی**: آدرس سایت، تأیید گوگل، اتصال API، نقشه سایت، robots، RSS، داده ساخت‌یافته، IndexNow و…
- **کارهایی که باید انجام شود**: فهرست اولویت‌دار ایرادها با نام مقاله‌های درگیر و لینک مستقیم به ویرایشگر. مثلاً «مقاله یتیم»، «بدون توضیحات متا»، «محتوای نازک»، «عنوان تکراری»، «به‌روزرسانی‌نشده».

### سئوی مقاله‌ها

جدول همه مقاله‌ها با: جایگاه گوگل، کلیک، نمایش، بازدید سایت، امتیاز سئو، شمار لینک‌های ورودی داخلی و نشانه‌های ایراد (بی‌توضیح متا، بی‌تصویر، بدون FAQ، بی‌ایندکس). قابل مرتب‌سازی بر اساس هر معیار.

با کلیک روی عنوان هر مقاله: **عبارت‌هایی که همان مقاله با آن‌ها دیده شده** و **وضعیت ایندکس شدنش در گوگل** (از URL Inspection) خوانده می‌شود، و یک دکمه برای اعلام فوری آدرس به موتورهای جستجو.

### تنظیمات سئو

آدرس سایت، لوگو و شبکه‌های اجتماعی برند (sameAs)، تصویر پیش‌فرض اشتراک‌گذاری، کدهای تأیید گوگل و بینگ، نویسنده پیش‌فرض، داده ساخت‌یافته صفحه اصلی، و IndexNow. پایین صفحه فهرست چیزهایی است که **خودکار** اعمال شده و نیازی به تنظیم ندارد.

### اتصال گوگل سرچ کنسول (برای دیدن جایگاه واقعی)

۱. در [Google Cloud Console](https://console.cloud.google.com) یک پروژه بسازید و **Search Console API** را فعال کنید.
۲. یک **Service Account** بسازید و برایش کلید JSON بگیرید.
۳. در سرچ کنسول → Settings → Users and permissions، ایمیل سرویس‌اکانت (مثل `...@...iam.gserviceaccount.com`) را به عنوان **Full user** اضافه کنید.
۴. در `.env` سرور بگذارید:

```bash
GSC_CLIENT_EMAIL="service-account@project.iam.gserviceaccount.com"
GSC_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n"
GSC_SITE_URL="https://pasargadmizban.ir/"
```

۵. اپلیکیشن را دوباره راه‌اندازی کنید. از این به بعد همه آمار در پنل می‌آید و نیازی به رفتن به سرچ کنسول نیست.

بدون این اتصال، همه بخش‌های درون‌سایتی (بازدید، امتیاز سئو، ایرادها، لینک‌های داخلی) کار می‌کنند و فقط ستون‌های گوگل خالی می‌مانند.

### سرعت ایندکس شدن — واقعیت‌ها

- **بینگ و یاندکس**: با IndexNow، معمولاً چند دقیقه تا چند ساعت. این خودکار انجام می‌شود.
- **گوگل**: هیچ API عمومی برای «همین حالا ایندکس کن» وجود ندارد (Indexing API فقط برای آگهی شغلی و رویداد زنده مجاز است و استفاده از آن برای مقاله، نقض شرایط گوگل است). چیزی که واقعاً کار می‌کند:
  ۱. نقشه سایت ثبت‌شده در سرچ کنسول (یک بار)،
  ۲. لینک داخلی از صفحه‌های قدیمی‌تر به مقاله تازه (خودکار انجام می‌شود: هر مقاله به مقاله‌های دیگر لینک می‌دهد و در فهرست و پابرگ هم می‌آید)،
  ۳. برای مقاله‌های مهم، یک بار **URL Inspection → Request Indexing** در سرچ کنسول،
  ۴. انتشار منظم؛ سایتی که هر روز مطلب تازه دارد، بیشتر خزیده می‌شود.

  برای دامنه تازه، معمولاً ۳ تا ۱۴ روز تا ایندکس شدن و ۱ تا ۳ ماه تا رسیدن به جایگاه واقعی طول می‌کشد. هیچ تنظیمی این را به چند روز کم نمی‌کند؛ هر کسی خلافش را بگوید، چیزی برای فروش دارد.

## ۵) پرسش‌های پرتکرار فنی

**مقاله زمان‌بندی‌شده چطور منتشر می‌شود؟**
به کرون نیازی نیست. مقاله‌ای که وضعیتش «زمان‌بندی‌شده» است و تاریخ انتشارش رسیده باشد، خودکار در فهرست‌ها و نقشه سایت دیده می‌شود.

**چرا بازدیدها با رفرش صفحه بالا نمی‌رود؟**
هر بازدیدکننده در هر ۶ ساعت یک بار شمرده می‌شود و شمارش در مرورگر و با تأخیر انجام می‌شود تا خزنده‌ها شمرده نشوند.

**تصویرها را کجا آپلود کنم؟**
فعلاً فیلد تصویر، آدرس می‌گیرد. تصویر را در `public/uploads/` بگذارید و مسیرش را وارد کنید (`/uploads/نام-فایل.webp`) یا از یک سرویس تصویر بیرونی استفاده کنید.

**دکمه ثبت‌نام به آدرس اشتباه می‌رود (مثل سایت اصلی به جای پنل ابری).**
سه چیز را به ترتیب بررسی کنید:

۱. **قاعده ریدایرکت وب‌سرور.** اگر در Nginx خطی مثل `location = /register { return 301 ...; }` دارید، همان دارد مسیر را عوض می‌کند. حذفش کنید و `systemctl reload nginx`.
۲. **تنظیم آدرس پنل ابری.** در مدیریت ← سئو و آمار ← تنظیمات سئو، فیلد «آدرس پنل ابری» باید پر باشد (مثل `https://cloud.example.com`). تا پر نشود، دکمه‌ها نمی‌دانند کاربر را کجا بفرستند و پنل هم بالای همان صفحه هشدار می‌دهد. از خط فرمان هم می‌شود، بدون باز کردن پنل:

```bash
npm run blog:configure -- --cloud https://cloud.example.com --main https://example.com --site https://blog.example.com
# بدون آرگومان، فقط وضعیت فعلی و مقصد دکمه‌ها را نشان می‌دهد:
npm run blog:configure
```

اگر خروجی `href="/register"` دیدید (لینک نسبی)، یعنی همین تنظیم خالی است.
۳. **لینک‌های داخل مقاله‌های قبلی.** مقاله‌هایی که پیش از این تنظیم ساخته شده‌اند، لینک نسبی `/register` دارند. یک بار این دستور را اجرا کنید تا همه‌شان به پنل ابری منتقل شوند:

```bash
npm run blog:fix-links
# داکر:
docker compose run --rm app npm run blog:fix-links
```

این دستور HTML و امتیاز سئوی مقاله‌ها را هم دوباره می‌سازد و فقط مقاله‌هایی را لمس می‌کند که لینک نسبی دارند.

**وبلاگ را موقتاً خاموش کنم؟**
در تنظیمات سئو، کلید «وبلاگ روی سایت فعال باشد» را خاموش کنید؛ همه صفحه‌ها و لینک‌هایش برداشته می‌شوند.

**مقاله‌ای که نمی‌خواهم در گوگل بیاید؟**
در ویرایشگر، کلید «از گوگل پنهان شود (noindex)» را روشن کنید. از نقشه سایت و خوراک RSS هم حذف می‌شود.
