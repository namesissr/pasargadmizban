# انتقال کامل سایت به سرور جدید

این راهنما سایت را با همه داده‌هایش (مقاله‌ها، تنظیمات، کاربران، آمار، گواهی SSL) از سرور فعلی به سرور تازه منتقل می‌کند. دامنه و نشانی صفحه‌ها عوض نمی‌شود، پس رتبه گوگل از دست نمی‌رود. سایت در کل کار فقط چند دقیقه، هنگام عوض شدن DNS، ممکن است در دسترس نباشد.

در دستورها به‌جای این‌ها مقدار واقعی را بگذارید:

- `OLD` — آی‌پی سرور فعلی
- `NEW` — آی‌پی سرور تازه
- `blog.pasargadmizban.com` — دامنه سایت (اگر فرق دارد)

کدام دستور روی کدام سرور اجرا شود، بالای هر بخش نوشته شده است.

---

## گام ۰ — یک روز قبل: کوتاه کردن TTL دامنه

در پنل DNS دامنه، TTL رکورد A مربوط به `blog` را روی کمترین مقدار (مثلاً ۳۰۰ ثانیه) بگذارید. این‌طور در گام ۶، تغییر آی‌پی در چند دقیقه همه‌جا دیده می‌شود. اگر این کار را نکنید هم انتقال انجام می‌شود، فقط عوض شدن آی‌پی دیرتر به همه می‌رسد.

---

## گام ۱ — آماده‌سازی سرور تازه — روی NEW

```bash
apt update && apt upgrade -y
apt install -y ufw curl git rsync nginx certbot python3-certbot-nginx

# فایروال: فقط SSH، HTTP و HTTPS
ufw allow OpenSSH
ufw allow 80/tcp
ufw allow 443/tcp
ufw --force enable

# داکر
curl -fsSL https://get.docker.com | sh
docker compose version
```

---

## گام ۲ — کپی فایل‌های پروژه، تنظیمات Nginx و گواهی SSL — روی OLD

این دستورها از سرور فعلی به سرور تازه کپی می‌کنند (بار اول رمز root سرور تازه را می‌پرسد):

```bash
apt install -y rsync

# کد پروژه به همراه .env (بدون فایل‌های ساختنی که دوباره ساخته می‌شوند)
rsync -a --info=progress2 --exclude node_modules --exclude .next /opt/panel/ root@NEW:/opt/panel/

# تنظیمات Nginx و گواهی Let's Encrypt
rsync -a /etc/nginx/sites-available/ root@NEW:/etc/nginx/sites-available/
rsync -a --delete /etc/nginx/sites-enabled/ root@NEW:/etc/nginx/sites-enabled/
rsync -a /etc/letsencrypt/ root@NEW:/etc/letsencrypt/
```

فایل `.env` کلیدهای حساس دارد (رمز دیتابیس، کلید هوش مصنوعی و…). با همین rsync مستقیم بین دو سرور منتقل می‌شود و جای دیگری نمی‌رود.

---

## گام ۳ — بیلد روی سرور تازه — روی NEW

```bash
cd /opt/panel
docker compose build app
docker compose up -d db
```

بیلد بار اول چند دقیقه طول می‌کشد. تا گام ۴ فقط دیتابیس روشن است.

---

## گام ۴ — انتقال دیتابیس

**روی OLD** — اول ورکر را خاموش کنید تا در فاصله انتقال مقاله تازه‌ای خودکار منتشر نشود. سایت همچنان بالاست:

```bash
cd /opt/panel
docker compose stop worker
docker compose exec -T db pg_dump -U pasargad -Fc pasargad_cloud > /root/panel.dump
ls -lh /root/panel.dump
scp /root/panel.dump root@NEW:/root/
```

از این لحظه تا پایان گام ۶، در پنل سرور قدیم مقاله ویرایش یا منتشر نکنید؛ تغییرهای بعد از گرفتن نسخه پشتیبان به سرور تازه نمی‌رسد.

**روی NEW**:

```bash
cd /opt/panel
docker compose exec -T db pg_restore -U pasargad -d pasargad_cloud --no-owner --clean --if-exists < /root/panel.dump
docker compose run --rm app npm run db:push
docker compose up -d
docker compose ps
```

هر سه سرویس `db`، `app` و `worker` باید `running` (یا `healthy`) باشند. اگر `pg_restore` چند هشدار درباره چیزهایی داد که وجود نداشتند («does not exist»)، طبیعی است.

---

## گام ۵ — آزمایش پیش از عوض کردن DNS — روی NEW

```bash
nginx -t && systemctl reload nginx

# خود برنامه
curl -s -o /dev/null -w "app: %{http_code}\n" http://127.0.0.1:3000/blog

# از راه Nginx و HTTPS، با همان دامنه (DNS هنوز به سرور قدیم اشاره می‌کند)
curl -s -o /dev/null -w "https: %{http_code}\n" --resolve blog.pasargadmizban.com:443:127.0.0.1 https://blog.pasargadmizban.com/blog
curl -s --resolve blog.pasargadmizban.com:443:127.0.0.1 https://blog.pasargadmizban.com/sitemap.xml | head -c 300; echo
```

باید `200` ببینید و نقشه سایت با نشانی‌های درست بیاید.

برای دیدن سایت تازه در مرورگر خودتان پیش از عوض کردن DNS، روی کامپیوترتان در فایل hosts این خط را بگذارید و بعد از آزمایش برش دارید:

- ویندوز: `C:\Windows\System32\drivers\etc\hosts`
- مک/لینوکس: `/etc/hosts`

```
NEW  blog.pasargadmizban.com
```

ورود به پنل مدیریت، فهرست مقاله‌ها، یک مقاله، تصویرها و صفحه «سئو و آمار» را امتحان کنید.

---

## گام ۶ — عوض کردن DNS

در پنل DNS دامنه، رکورد A مربوط به `blog` را از `OLD` به `NEW` تغییر دهید. اگر دامنه پشت CDN (مثلاً آروان یا کلادفلر) است، آی‌پی مبدأ را در همان CDN عوض کنید.

بررسی (از هر جایی):

```bash
dig +short blog.pasargadmizban.com
```

وقتی آی‌پی تازه را نشان داد، سایت از سرور تازه سرو می‌شود.

---

## گام ۷ — کارهای بعد از انتقال — روی NEW

```bash
# تمدید خودکار گواهی روی سرور تازه
certbot renew --dry-run

# بکاپ شبانه دیتابیس (هر شب ۳:۳۰، نگهداری ۱۴ نسخه آخر)
crontab -e
```

این خط را اضافه کنید:

```
30 3 * * * cd /opt/panel && docker compose exec -T db pg_dump -U pasargad pasargad_cloud | gzip > /root/db-$(date +\%F).sql.gz && ls -t /root/db-*.sql.gz | tail -n +15 | xargs -r rm
```

و در پایان فایل پشتیبان انتقال را پاک کنید:

```bash
rm -f /root/panel.dump
```

اگر «سرویس آزمایش دسترسی از ایران» را راه انداخته‌اید، روی **سرور ایرانی** پورتش را برای آی‌پی تازه هم باز کنید:

```bash
ufw allow from NEW to any port 8787 proto tcp
```

---

## گام ۸ — سرور قدیم — روی OLD

سرور قدیم را چند روز (۳ تا ۷ روز) نگه دارید تا مطمئن شوید همه چیز روی سرور تازه درست است؛ ولی **ورکر را روشن نکنید**. اگر هر دو سرور ورکر روشن داشته باشند، هر دو مقاله تولید و منتشر می‌کنند.

بعد از اطمینان:

```bash
cd /opt/panel
docker compose down
rm -f /root/panel.dump
```

و سرور را تحویل دهید. پیش از تحویل، اگر روی دیسک چیز حساسی هست (`.env`، `.env.bak`، بکاپ‌ها)، پاکش کنید. فایل `.env.bak` با rsync به سرور تازه هم رفته است؛ اگر لازمش ندارید آنجا هم پاکش کنید.

---

## گوگل و سئو

- دامنه و نشانی صفحه‌ها همان است؛ در سرچ کنسول کاری لازم نیست و رتبه‌ها حفظ می‌شوند.
- Googlebot چند روز اول ممکن است سرعت خزیدن را کمی پایین بیاورد تا سرور تازه را بسنجد؛ طبیعی است.
- کلید IndexNow در دیتابیس است و همراه آن منتقل شده است.

## عیب‌یابی

| نشانه | علت معمول | راه‌حل |
|---|---|---|
| `502 Bad Gateway` | برنامه بالا نیامده | `docker compose ps` و `docker compose logs app --tail 50` |
| خطای اتصال به دیتابیس | رمز `POSTGRES_PASSWORD` با دیتابیس نمی‌خواند | همان `.env` سرور قدیم را بی‌تغییر کپی کنید و `docker compose up -d` |
| مقاله‌ها نیستند | `pg_restore` اجرا نشده یا خطا داده | گام ۴ را تکرار کنید و خروجی خطا را بخوانید |
| خطای گواهی در مرورگر | پوشه `/etc/letsencrypt` کامل کپی نشده | گام ۲ را تکرار کنید، یا بعد از عوض شدن DNS: `certbot --nginx -d blog.pasargadmizban.com` |
